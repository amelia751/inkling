# Working on Inkling

pnpm monorepo; the app is `apps/web` (React 19, Vite 7, TypeScript, zustand, Tailwind +
shadcn). Seed data is fetched locally with `pnpm seeds` and is gitignored.

## Checks

Run these in `apps/web` before you hand work back:

- `pnpm typecheck`
- `pnpm test` (vitest unit tests: platform, kits, modules)
- `pnpm check:boundaries` and `pnpm check:icons`
- `pnpm emit:schemas --check` (fails if generated schemas are stale; run `pnpm emit:schemas`)
- e2e: start a frozen dev server with `INKLING_E2E=1 pnpm exec vite --port 5199 --strictPort`,
  then run `python3 e2e/<name>_test.py --port 5199`. The `data-testid`s and store fields
  those tests use are a regression contract: keep them working.

## Architecture in one paragraph

The Studio shell runs an **environment** (JSON) that references **modules**. Modules live
in `src/modules/<id>/` and contribute data kinds, renderers, tools, commands, panels,
inspectors, exporters, label controls, review rules and presets. Shared building blocks
are **kits** (`src/kits/`). Contracts, the registry, resolver, `when` clauses, commands and
runtime context are the **platform** (`src/platform/`). Read `docs/modules.md`.

## Adding a module

1. Copy `src/modules/_template/` to `src/modules/<name>/`, rename its id (`inkling.<name>`).
2. Write `manifest.ts`: pure data (types, icons, zod schemas, small pure functions such as
   `groupItems`). Every contribution gets a one-line `description`; add an `example` when
   the default one (generated by the catalogue) isn't a good snippet.
3. Put components and heavy code behind `load()` in `impl.ts`.
4. Renderers get everything from `RendererProps` (`env`, `viewport`, `item`, `config`,
   `runtime`) and write annotations through `useStudio`. Publish live values with
   `runtime.publish`, never module-level singletons.
5. Bind keys with `useCommands({ name: handler }, { scope: "inkling.<name>" })`; declare the
   command (keys, `when`, label) in the manifest. Never hard-code a key in a component.
6. Register the module in `src/bundle.ts` (one import, one array entry).
7. Add a preset (`src/platform/presets/<id>.json`) if it boots a Studio on its own.
8. Run `pnpm emit:schemas` and add an e2e smoke test.

## Rules

- Platform imports nothing from kits, modules or Studio components. Kits never import
  modules. A module imports another module only through its `manifest.ts` or `public.ts`.
  The shell reaches modules only through the registry.
- Domain constants (WFDB codes, cardiac structures, CT presets) live in module config
  defaults or preset vocabularies, never in kits or the platform.
- Core geometries are domain-neutral (`box`, `polygon`, `span`, `instant`…); domain meaning
  goes in `annotation.attributes`. Stored v1 geometries migrate on load
  (`src/migrations/annotations-v1-to-v2.ts`).
- Icons come only from `@/components/icons`.
- Never hand-edit generated files: `public/catalog.json`, `public/catalog.md`,
  `public/schema/environment.v1.json`, `docs/modules-reference.md`.
